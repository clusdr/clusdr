# Configuration

One daemon is configured in three places: YAML, `data.dir`, and `CLUSDR_*`. Pin paths, ports, or TLS here after `clusdr init`. This is not a second product mode and it does not start the process.

Three places, three jobs:

| Thing | Default | Role | Why it matters |
|---|---|---|---|
| YAML | `clusdr.yaml` in the current directory (`--config`) | This process’s knobs | `~` is not expanded; a typo only shows up at `start` unless you `config validate`. |
| `data.dir` | `$HOME/.clusdr` (`HOME` unset → `/var/lib/clusdr`) | Identity, Raft log, certs | Two processes sharing this dir is undefined (BoltDB flock / certs). |
| `grpc.control_socket` | `$HOME/.clusdr/clusdr.sock` | `clusdr status` file check | Not a Kubernetes probe; prefer `clusdr members`. |

`install.sh` does not create any of these. It only puts the binary on `PATH`. YAML appears at `clusdr init`. Data dir and socket appear when that process first writes them (`init` / `start`).

Merge order (last wins): built-in defaults → YAML → `CLUSDR_*`. Flags `--log-level` / `--log-format` override that invocation only.

`clusdr config validate` prints the **resolved** struct (defaults + file + env). It does not start the daemon.

There is no laptop/server mode. Paths are whatever you set. `~` in YAML is **not** expanded.

## What `init` writes

`clusdr init` writes a **short** file (mode `0600`) at `--config` (default `./clusdr.yaml`). It is not the full schema. Missing keys keep their defaults.

```yaml
# Clusdr configuration
# Generated by 'clusdr init'
# See docs/reference/configuration.md for all options.

node:
    id: <generated>
    addr: 0.0.0.0:7947
cluster:
    id: <generated>
log:
    level: info
    format: text
```

`--force` overwrites this file **and** prints a new join token. That is not how you change ports or `data.dir`. Existing peers keep the old token hash and will reject the new one ([errors](errors.md#join)).

`node.id` and `cluster.id` are also in `data.dir` (`state.db`). Do not invent new ids in YAML for a node that already has a store.

## Change an existing file

1. Edit the YAML `init` (or you) created. Add only the keys you want to override.
2. `clusdr config validate --config /path/to/clusdr.yaml` — confirm the merge.
3. Stop the daemon and `clusdr start` with the **same** `--config`. The process does not reload on SIGHUP.

CLI commands that talk to the daemon (`members`, `join`, …) must use that same `--config` so they see the same `grpc.addr` and `data.dir`. Apps do not read YAML; they dial `CLUSDR_GRPC_ADDR` or `127.0.0.1:7947` and load PEMs from `CLUSDR_DATA_DIR` or `$HOME/.clusdr`.

A second process on the same machine needs its own file, `data.dir`, ports, and socket — [grow](../guide/grow.md).

## Laptop

No extra paths. From the directory where you ran `init`:

```bash
clusdr start --bootstrap
clusdr config validate
clusdr members
```

State and socket: `$HOME/.clusdr`. Runtime API: `127.0.0.1:7947`. To move data off home, add to that yaml (then restart):

```yaml
data:
  dir: /home/you/clusdr-data
grpc:
  control_socket: /home/you/clusdr-data/clusdr.sock
```

## On a server

Pin `--config` so cwd does not matter. Example after `clusdr init --config /etc/clusdr/clusdr.yaml` — keep the generated ids, then add:

```yaml
node:
  id: <from-init>
  addr: 10.0.0.10:7947    # dialable; not 0.0.0.0
cluster:
  id: <from-init>
data:
  dir: /var/lib/clusdr
log:
  level: info
  format: json
grpc:
  addr: 127.0.0.1:7947    # or 10.0.0.10:7947 if other hosts must dial Runtime
  control_socket: /run/clusdr/clusdr.sock
raft:
  addr: 10.0.0.10:7946
lease:
  presence: true
  presence_ttl: 15s       # how fast member.dead after a crash; not an eject
```

Env is equivalent and wins over YAML:

```bash
CLUSDR_DATA_DIR=/var/lib/clusdr
CLUSDR_CONTROL_SOCKET=/run/clusdr/clusdr.sock
CLUSDR_RAFT_ADDR=10.0.0.10:7946
```

No packaged systemd unit. A unit that pins the file:

```ini
[Service]
ExecStart=/usr/local/bin/clusdr start --config /etc/clusdr/clusdr.yaml --bootstrap
# later members: drop --bootstrap
Restart=always
```

`--bootstrap` only on the first voter. Do not put `clusdr join` on every boot. Join is first add (or after `clusdr leave`). A reboot is `clusdr start` with the same `data.dir` ([presence](../concepts/presence.md)).

Docker image defaults `CLUSDR_DATA_DIR=/var/lib/clusdr` — [other hosts](../guide/other-hosts.md).

## All keys

Only keys that exist in code. Heartbeat and `shutdown_timeout` are YAML-only.

```yaml
node:
  id: ""                 # set by init; required for a joining node
  addr: "0.0.0.0:7947"   # advertised member address — dialable host:port
cluster:
  id: ""                 # set by init
data:
  dir: ""                # default $HOME/.clusdr; /var/lib/clusdr if HOME unset
log:
  level: info            # debug | info | warn | error
  format: text           # text | json
grpc:
  addr: "127.0.0.1:7947"
  control_socket: ""     # default $HOME/.clusdr/clusdr.sock
  dial_timeout: 5s
  request_timeout: 10s
shutdown_timeout: 15s    # only applied if > 0; otherwise process default 15s
heartbeat:
  interval: 2s
  timeout: 1s
  max_misses: 3
raft:
  addr: "127.0.0.1:7946"
  bootstrap: false
  heartbeat_timeout: 150ms
  election_timeout: 150ms
  leader_lease_timeout: 75ms
tls:
  mode: enabled          # enabled | disabled
lock:
  ttl: 15s
  expire_interval: 100ms
lease:
  ttl: 15s
  expire_interval: 100ms
  presence: true
  presence_ttl: 3s       # how fast member.dead; crash is not leave
```

`leader_lease_timeout` must be ≤ `heartbeat_timeout`. If an override breaks that, load clamps lease to half the heartbeat.

TLS is **on** unless every node and client sets `CLUSDR_TLS=disabled`. A mixed cluster fails the handshake ([errors](errors.md#tls)).

## Environment

| Variable | Sets |
|---|---|
| `CLUSDR_NODE_ID` | `node.id` |
| `CLUSDR_NODE_ADDR` | `node.addr` |
| `CLUSDR_CLUSTER_ID` | `cluster.id` |
| `CLUSDR_DATA_DIR` | `data.dir` |
| `CLUSDR_LOG_LEVEL` | `log.level` |
| `CLUSDR_LOG_FORMAT` | `log.format` |
| `CLUSDR_GRPC_ADDR` | `grpc.addr` |
| `CLUSDR_CONTROL_SOCKET` | `grpc.control_socket` |
| `CLUSDR_RAFT_ADDR` | `raft.addr` |
| `CLUSDR_RAFT_BOOTSTRAP` | `raft.bootstrap` when `true` or `1` |
| `CLUSDR_RAFT_HEARTBEAT_TIMEOUT` | duration |
| `CLUSDR_RAFT_ELECTION_TIMEOUT` | duration |
| `CLUSDR_RAFT_LEADER_LEASE_TIMEOUT` | duration |
| `CLUSDR_TLS` | `tls.mode` (`disabled` / `off` / `false` / `0` turn TLS off) |
| `CLUSDR_LOCK_TTL` | duration |
| `CLUSDR_LOCK_EXPIRE_INTERVAL` | duration |
| `CLUSDR_LEASE_TTL` | duration |
| `CLUSDR_LEASE_EXPIRE_INTERVAL` | duration |
| `CLUSDR_LEASE_PRESENCE` | bool (`true`/`1`/`on`/`enabled`, or off) |
| `CLUSDR_LEASE_PRESENCE_TTL` | duration |

CLI `--bootstrap` injects `CLUSDR_RAFT_BOOTSTRAP=true` for that process only.

SDK extra: `CLUSDR_TLS_SERVER_NAME` is read by the Python, Rust, TypeScript, and Java clients when `node.crt` has no CN. Set it to the **peer node id**. The Go SDK does not read this variable. All five SDKs locate PEM files the same way ([Security](../concepts/security.md)).

`CLUSDR_SHUTDOWN_TIMEOUT` is **not** implemented.
